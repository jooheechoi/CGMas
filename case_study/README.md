# Case study 1 — Polyethylene at one bead per monomer

The complete CGMas run: a linear hydrocarbon backbone mapped at one bead per repeat unit, executed end to end from a single query with no human intervention.

Start here if you are new to CGMas. It exercises every stage of the pipeline — topology generation and self-correction, all-atom equilibration, bead mapping, potential derivation, CG equilibration, *T*<sub>g</sub> extraction, and validation — on a chemistry simple enough that each intermediate result can be checked by inspection.

**Runtime:** about 45 min on the reference workstation (Intel Core i7-14700K, 12 MPI processes), almost all of it the all-atom equilibration.

## 1. Running it

```python
from CGMas import run_cgmas_auto        # or execute the notebook cells

run_cgmas_auto("Run simulation of polyethylene aa and cg. EQ simulation time for 1 ns. Set 1 bead per monomer.")
```

Equivalently, from the notebook, execute cells and then:

```python
session_dir = run_cgmas_auto("Run simulation of polyethylene aa and cg. EQ simulation time for 1 ns. Set 1 bead per monomer.")
print(session_dir)
```

That single sentence is the entire input. The polymer name, the architecture, and the target resolution are all parsed from it; every remaining decision — atom typing, box size, annealing protocol, interaction types — is made by the framework under its defaults.

To step through the same task with confirmation at each checkpoint, use `run_cgmas()` instead and answer the prompts. See [§5](#5-running-it-interactively).

## 2. What happens, stage by stage

### 2.1 Topology

The topology agent identifies polyethylene as a vinyl homopolymer with the constitutional repeat unit **–CH<sub>2</sub>–CH<sub>2</sub>–**: two sp³ carbons of OPLS-AA type `CT` and four alkane hydrogens of type `HC`, six atoms in total, summing to zero net charge.

**This run is instructive because the first attempt fails.** One topology was flagged as invalid during self-correction and regenerated before the constructor was allowed to proceed. Read `session/chat_log.json` to see which validator fired and what feedback it returned — the validator reports the quantitative discrepancy and the local bonding context, not a corrected assignment, and the agent re-derives the repair from the structure itself. Polyethylene is the clearest place to watch this mechanism, because the correct answer is obvious to a human reader and the failure is therefore easy to interpret.

### 2.2 All-atom system

Under the defaults — 20 chains × 10 repeat units at 0.9 g cm<sup>−3</sup> — the constructor packs 620 atoms (600 backbone atoms plus 20 chain-terminating hydrogens) into a cubic periodic box. Coordinates are generated by breadth-first traversal with Z-matrix placement, torsions sampled uniformly to give amorphous conformations, and steric clashes removed by adaptive overlap rejection.

Conjugate-gradient minimization is followed by one annealing cycle from 300 K to 500 K and back, then 1000 ps of NPT equilibration at 300 K.

**Check this before trusting anything downstream.** Open `aa_density.png`, `aa_temperature.png`, and `aa_potential_energy.png` from the session directory. All three must reach a steady mean and then fluctuate stationarily. The accumulated distributions inherit any residual drift of this trajectory.

### 2.3 Mapping

At one bead per monomer, all six atoms of the repeat unit map to a single bead type, giving a 200-bead CG representation — a factor of 3.1 fewer interaction sites than the atomistic system. The bead mass is the summed atomic mass of the repeat unit, 28.05 amu.

This is the degenerate case of the mapping stage: one bead type, one bond type (A–A), one angle type (A–A–A), one LJ pair type (A–A). Later case studies exercise multi-bead mappings.

### 2.4 Potentials

Distributions are accumulated from the mapped trajectory and Boltzmann-inverted, then fitted to harmonic bond and angle forms and a 12-6 Lennard-Jones pair form. Each LJ ε is then rescaled to reproduce the all-atom intermolecular cohesive energy per bead (energy matching; see manual §7.5).

| Term | Parameter | Value |
|---|---|---|
| A–A bond | *r*<sub>0</sub> | 2.55 Å |
| A–A–A angle | *θ*<sub>0</sub> | 179.2° |
| A–A pair | *σ* | 4.54 Å |

The angle equilibrium sits close to 180°, which is the expected signature of a one-bead-per-monomer mapping of a linear backbone: successive bead centres of mass lie nearly on a line, so the angular distribution peaks against the upper bound of its range. The derived force constant is correspondingly soft. If your run returns *θ*<sub>0</sub> well below 170°, check the mapping before the potential — an angle that stiff usually means the partition placed beads on atoms that are not consecutive along the chain.

Full parameters, including force constants and ε, are in `session/potentials.json`. Compare `*_dist.png` against your own run: the sampled distributions and the inverted curves should overlay closely for this chemistry.

### 2.5 CG simulation and validation

The CG model is assembled from the fitted parameters and equilibrated under the same thermal protocol as the AA system. A cooling scan then locates the glass transition by bilinear fit of the density–temperature curve.

| Quantity | CG | Criterion | Result |
|---|---|---|---|
| Equilibrium density | 0.73 g cm<sup>−3</sup> | within 5% of AA | **1.80% — pass** |
| Glass transition | 190.1 K | within 15 K of AA | **8 K — pass** |

The AA reference for both quantities is produced in the same session under the identical protocol and chain length, so the residual deviation reflects the coarse-graining step rather than a difference in reference state.

## 3. Reproducing the robustness results

Polyethylene is the chemistry used for both robustness tests in the paper, so this directory is also where those results are reproduced.

### 3.1 Construction and simulation parameters

Seven configurations, five repetitions each. Every configuration passed.

| Condition | *N*<sub>m</sub> | *N*<sub>c</sub> | *T* (K) | Density error (%) | Cost (10<sup>−3</sup> USD) |
|---|---|---|---|---|---|
| Default | 10 | 20 | 300 | 1.80 ± 0.016 | 1.85 ± 0.03 |
| Lower *T* | 10 | 20 | 250 | 1.42 ± 0.015 | 1.92 ± 0.01 |
| Higher *T* | 10 | 20 | 350 | 2.99 ± 0.020 | 1.84 ± 0.03 |
| Longer, fewer chains | 20 | 10 | 300 | 2.01 ± 0.015 | 1.87 ± 0.02 |
| Longer chains | 20 | 20 | 300 | 1.54 ± 0.011 | 1.89 ± 0.02 |
| Longest, fewer chains | 40 | 10 | 300 | 1.29 ± 0.010 | 1.98 ± 0.01 |
| More chains | 10 | 40 | 300 | 1.40 ± 0.008 | 1.87 ± 0.02 |

Two things to read from this table. The largest deviation occurs at 350 K, the state point furthest from where the potentials were derived, which is the expected behaviour of a structure-based CG model rather than a failure of the framework. And the reasoning cost barely moves across configurations, which shows that the cost of automation is set by the chemistry of the repeat unit, not by the size or temperature of the system it builds.

Reproduce a row by stating the parameters in the query:

```python
run_cgmas_auto(
    "Simulate polyethylene at 1 bead per monomer. Use 10 chains of 40 repeat "
    "units, equilibrated at 300 K."
)
```

### 3.2 Reasoning backbone

The same task, five repetitions per backbone. All five completed the pipeline and passed validation.

| | 5.4-nano | 5.4-mini | 5.5 | Haiku 4.5 | Sonnet 5 |
|---|---|---|---|---|---|
| Density error (%) | 2.13 ± 0.020 | 1.80 ± 0.016 | 2.55 ± 0.002 | 2.46 ± 0.006 | 2.49 ± 0.010 |
| LLM calls | 27.7 ± 2.4 | 25.0 ± 0.0 | 26.3 ± 1.8 | 21.0 ± 2.9 | 20.3 ± 3.3 |
| Cost (10<sup>−3</sup> USD) | 2.15 ± 0.06 | 1.85 ± 0.03 | 6.91 ± 2.53 | 28.74 ± 4.76 | 46.68 ± 2.23 |

Density errors fall in a narrow band while cost varies by a factor of roughly 25. This is the basis for adopting `gpt-5.4-mini` as the default: it was both the least expensive backbone tested and the most accurate.

To reproduce a column, change the backbone as described in manual §3.2 and re-run the same query. Note that the number of LLM calls, and therefore the cost, varies between repetitions even at `temperature=0`, because the number of self-correction cycles varies. The density does not.

## 4. Verifying your run

Compare against `session/` in this directory.

**Should match closely.** The CRU composition (2 `CT` + 4 `HC`, net charge 0), the atom count (620), the bead count (200), the box dimensions, the interaction-type inventory (1 bond, 1 angle, 1 pair type), and both validation outcomes.

**Should match to within a few per cent.** The fitted parameters, the equilibrium densities, and *T*<sub>g</sub>. The construction seed is fixed by default (`DEFAULT_SEED = 42`), so the coordinates are identical for an identical topology; the residual variation comes from small differences in the generated topology and fitted parameters.

**Will not match, and need not.** The number of LLM calls, the token counts, the cost, and the number of self-correction cycles. Wall-clock times depend on your hardware and MPI configuration.

**If your density error exceeds 5%,** work backwards: check the AA property traces for stationarity first, then the derived *θ*<sub>0</sub> against the value above, then the CRU in `chat_log.json`. For polyethylene an error this large almost always traces to an unconverged reference rather than to the coarse-graining.

## 5. Running it interactively

The same task with confirmation at each checkpoint. Useful for seeing what the framework decides at each stage and for changing a decision mid-run.

```python
run_cgmas("Study CGMD simulation of polyethylene. Start with all-atomistic simulations.")
```

Suggested replies:

| Checkpoint | Reply |
|---|---|
| System and protocol | `Run 1 annealing cycle from 300 K to 500 K, then simulate for 1000 ps at 300 K.` |
| Bead mapping | `1 monomer = 1 bead` |
| Potential approval | `looks good, proceed` |
| CG simulation | `ok, let's start the coarse-grained simulation` |
| *T*<sub>g</sub> annealing | `yes, run the Tg annealing` |
